# BuildRMC Fortune Dashboard

## Overview

Full-stack enterprise ERP for Ready Mix Concrete companies. Built as a pnpm monorepo with React + Vite frontend and Express 5 + PostgreSQL backend.

## Stack

- **Monorepo tool**: pnpm workspaces
- **Node.js version**: 24
- **Package manager**: pnpm
- **TypeScript version**: 5.9
- **Frontend**: React + Vite + Tailwind CSS + Wouter routing + TanStack Query
- **Backend**: Express 5 + Drizzle ORM + PostgreSQL
- **Validation**: Zod (`zod/v4`), `drizzle-zod`
- **API codegen**: Orval (from OpenAPI spec → React Query hooks + Zod schemas)
- **Build**: esbuild (CJS bundle for API server)

## Modules (12 post-login)

1. **Dashboard** – KPI summary cards, sales trend chart (Recharts), recent activity feed
2. **Billing** – Invoice List page with KPI cards (today/yesterday/week/month quantity, bill not received), filters (invoice no, date range, customer, unit/plant), table with toggle for `isBillReceived`, pagination, Copy/CSV/PDF export; Add Invoice form with advance options (CGST/SGST/IGST, loaded plant, pump charge, transport charge)
3. **DC (Delivery Challan)** – Delivery challan management linked to invoices & vehicles
4. **Customers & PO** – Customer profiles + Purchase Orders
5. **Sales** – Sales order tracking
6. **QC** – Quality control tests (slump, strength, grade)
7. **Accounts** – Chart of accounts + ledger entries
8. **Store** – Product/inventory management + inventory entries
9. **Transport** – Vehicle fleet + trip management
10. **HRM** – Employees, attendance, payroll
11. **Reports** – Sales summary + inventory analytics

## Authentication

- Cookie-based (`userId` cookie), httpOnly=false for JS access
- Admin credentials: `admin` / `admin123` (hardcoded)
- DB users also supported
- API routes: `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`

## Key Commands

- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- `pnpm --filter @workspace/api-server run dev` — run API server locally

## Database Schema

Tables: `users`, `customers`, `purchase_orders`, `invoices`, `delivery_challans`, `sales_orders`, `qc_tests`, `accounts`, `ledger_entries`, `products`, `inventory_entries`, `vehicles`, `trips`, `employees`, `attendance`, `payroll`

All monetary/numeric Drizzle fields stored as `numeric` (string in JS) — route handlers convert with `parseFloat()`.

`invoices` table extended with: `plant`, `loadedPlant`, `kmReading`, `block`, `site`, `invoiceTime`, `driverName`, `vehicleId`, `vehicleNo`, `pumpType`, `grade`, `loadedGrade`, `loadedQuantity`, `quantity`, `netAmount`, `netPrice`, `pumpCharge`, `transportCharge`, `cgstRate`, `sgstRate`, `igstRate`, `remark`, `isBillReceived`.

## Packages

- `lib/api-spec` — OpenAPI YAML spec (source of truth)
- `lib/api-zod` — Zod schemas generated from OpenAPI
- `lib/api-client-react` — React Query hooks generated from OpenAPI (via Orval)
- `lib/db` — Drizzle ORM schema + DB client
- `artifacts/api-server` — Express API server with all route handlers
- `artifacts/buildrmc` — React + Vite frontend

## Gotchas

- `lib/api-zod/src/index.ts` is regenerated by orval on every codegen run. The orval `schemas` config also generates TS interfaces in `generated/types/` whose names collide with the zod consts in `generated/api.ts`. Keep `index.ts` as just `export * from "./generated/api";` and re-apply this after each codegen run if needed (the TS types in `generated/types/` are unused — clients import types from `@workspace/api-client-react`).
